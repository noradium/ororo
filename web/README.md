# おろろの記録 — 家族で使うPWA

モネ（グレーのブリティッシュショートヘアー）とルノワール（白のラガマフィン）の、トイレ・ご飯廃棄量・嘔吐を記録します。iPhone・Androidともブラウザーで開き、ホーム画面に追加して使えます。

## 端末だけで試す

Node.js 24、npmを使用します。

```sh
cd web
npm ci
npm run dev
```

Firebase設定がなければ端末保存モードになります。記録はIndexedDBに保存され、再起動しても残ります。家族には共有されません。ブラウザーのデータ消去・プライベートモード終了・OSによるストレージ削除で失われる可能性があるため、大切な記録はJSONに書き出してください。

PWAのオフライン起動を試す場合は `npm run build && npm run preview` を使って、一度オンラインで画面を開いてから再読み込みします。Service Workerは本番ビルドで有効です。実際の配信にはHTTPSが必要です（開発用localhostは例外）。

## 無料プランで家族共有を接続する

Firebaseプロジェクトの作成と公開は、利用者自身のGoogleアカウントで行います。秘密鍵やサービスアカウントJSONは不要です。

1. Firebaseコンソールでプロジェクトを作成します。**Sparkプランのまま使い、請求先を登録・Blazeへ変更しないでください。** Google Analyticsの追加も不要です。
2. Authenticationの「ログイン方法」で「Google」を有効にし、プロジェクトのサポートメールを設定します。新規利用にメール/パスワード認証や電話番号認証は不要です。
3. Cloud Firestoreの **Standardエディション・デフォルトデータベース `(default)`** を作成します。場所は例えば東京 `asia-northeast1`。本番モードを選び、公開読み書きのテストルールにはしません。
4. プロジェクト設定からWebアプリを追加します。表示されたWeb設定の4項目を `.env.example` からコピーした `.env.local` に設定します。

```dotenv
VITE_FIREBASE_API_KEY=Web設定のapiKey
VITE_FIREBASE_AUTH_DOMAIN=プロジェクトID.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=プロジェクトID
VITE_FIREBASE_APP_ID=Web設定のappId
VITE_USE_EMULATORS=false
```

このWeb設定はブラウザーに配信される公開メタデータです。管理者用の秘密鍵を入れないでください。アクセス制御は `firestore.rules` が行います。`.env.local` はGitに含めません。

5. 次のコマンドでルールとサイトを**一緒に**公開します。`YOUR_PROJECT_ID` は実際のプロジェクトIDに置き換えます。ここではCloud Functions・Cloud Run・Cloud Storage・有料ドメインは使いません。

```sh
cd web
npx firebase login
npm run build
npx firebase deploy --project YOUR_PROJECT_ID --only firestore,hosting
```

6. Authenticationの「設定 → 承認済みドメイン」で `YOUR_PROJECT_ID.firebaseapp.com` を確認します。Safari・iOS PWAのリダイレクト認証で別ドメインの保存領域に依存しないよう、配信URLは **`https://YOUR_PROJECT_ID.firebaseapp.com`** に統一します（同じFirebase Hostingサイトです）。ローカルで実プロジェクトを試す場合は `localhost` を手動で追加してください。
7. 公開したサイトの「Googleでログイン」からGoogleアカウントを選びます。初回も同じボタンで登録され、アプリ用のパスワードや確認メールは不要です。最初の人は家族グループを作成します。その後「招待リンクを作る」で、ほかの家族1人につき1本のリンクを渡します。
8. 招待された人は、招待リンクを開いて自分のGoogleアカウントでログインし、家族に参加します。招待リンクは**1回限り、6日間有効**です。1アカウントにつき家族グループは1つです。
9. 最初の端末で「保存・取り込み → 端末だけの記録を家族と共有する」を選ぶと、既存の端末保存データを共有できます。自動では外部に送信しません。

認証ドメインと同じ `https://YOUR_PROJECT_ID.firebaseapp.com` を家族で使います。iPhoneはSafariの共有メニュー →「ホーム画面に追加」、Androidはブラウザーのメニューからインストールできます。App Store・Google Playへの公開は不要です。

iPhoneではSafariとホーム画面版の保存領域が分かれる場合があります。切り替える前に家族共有へ同期するか、JSONを書き出して移してください。

無料枠は無制限ではありません。請求先を登録しないSparkプランでは無料枠を超えるとサービスが制限され、同期を再開できるまで未送信データは端末に残ります。Firestoreの使用量はコンソールで確認してください。アプリは表示中の1か月だけをリアルタイム購読し、全件読み込みは明示的な書き出し時に限っています。ルール検証・エミュレーターには実際のFirebaseプロジェクトは不要です。

## データ・同期のしくみ

- React + TypeScript + Viteの静的PWAです。既存のAndroid Java版はリポジトリの `app/` に残しています。
- 猫のIDは `MONET` / `RENOIR` / `UNASSIGNED`。時刻はエポックミリ秒、カレンダーは家族共通の日本時間です。ご飯は廃棄する残量を保存し、食べた量は自動計算しません。
- IndexedDBに記録と送信待ちを同じトランザクションで保存してから、画面に成功を表示します。送信待ちは再読み込み後も残ります。通信の復帰・画面の再表示・「再送」で同期を試します。
- 家族データの端末キャッシュと送信待ちは `ユーザーID + 家族ID` で分離します。ログアウト後に別のアカウントへ送信したり表示したりしません。同じアカウントで戻ると未送信データを再開します。ログアウトで端末上のキャッシュそのものを消すわけではありません。共用端末では端末のロックも使用してください。
- 記録は1件1ドキュメント。端末生成UUIDとトランザクションにより、再送・同じファイルの再取り込みで上書きや二重作成をしません。
- 猫の振り分けが同時に変更された場合は最後にサーバーで受け付けたものを採用します。削除は墓標として同期し、遅れて届いた変更より削除を優先します。削除は元に戻せません。
- 未送信データがある場合はPWAの更新を保留します。設定・通信・無料枠・権限のエラーがある場合、送信待ちは消さずに表示します。
- 招待は256ビットのランダムトークンで、URLのフラグメントに含めます。招待一覧の取得は禁止し、メール確認済みのGoogleアカウントで、招待の消費・参加者登録・ユーザーの家族紐付けを原子的に行えます。メンバー自身による管理者昇格はできません。
- グループ作成者以外のメンバーによる再招待はできません。メンバー削除UIはこの版には含めていません。作成者用の削除ルールはあり、必要ならFirebaseコンソールで `families/{familyId}/members/{uid}` を削除できます。権限を失う前に端末に保存した情報を遠隔消去する機能ではありません。

## Android版から移行

Android版の「すべての猫の記録を書き出す」でJSONを保存し、PWAの「保存・取り込み → Android版・PWAのJSONを取り込む」で選択します。家族共有する場合はログイン・家族参加を終えてから取り込んでください。

AndroidのJSONバージョン1・2、PWAのJSONバージョン3に対応します。旧版で猫が分からない記録は未分類のまま残し、履歴から振り分けます。同じIDは上書きしません。取り込み途中でストレージ制限などに失敗しても、同じファイルを再取り込みできます。削除済み記録は書き出しにも含め、再取り込みで復活させません。JSONファイルは20MB・50,000件以内です。

PWAの全件書き出しはログイン中の家族のデータ（端末内の未送信分を含む）です。ログアウト時は端末保存モードのデータが対象です。共有中は、過去に見た月だけの不完全なバックアップにならないようオンラインで全件取得します。

## 検証

```sh
npm ci
npm test
npm run build
npm run test:e2e
npm run test:auth
npm run test:rules
```

- `npm test`：移行、日付境界、スコープ分離、永続化、送信中の編集・削除、重複防止。
- `npm run test:e2e`：実ブラウザーで記録、猫切り替え、残量入力、再読み込み、削除、移行・書き出し、カレンダー、Service Workerによるオフライン起動・保存。
- `npm run test:auth`：Google資格情報の認証・確認済みクレーム・再ログイン、旧パスワードアカウントへの連携時のUID維持と、実ブラウザーでのGoogle認証セッション保持・ログアウト。テスト用の署名なしGoogleトークンはローカル認証エミュレーター専用で、本番では使用できません。
- `npm run test:google-popup`：認証エミュレーターのGoogle選択画面をブラウザーで操作し、ポップアップ・再読み込み・取消を確認します。外部SDKの `apis.google.com` の読み込みが必要です。ネットワーク制限で実行できない場合、成功として扱わないでください。
- `npm run test:rules`：エミュレーターで他家族・未認証・未確認メールの拒否、原子的な家族作成、招待の1回利用・期限・権限昇格防止、記録検証、削除復活防止、2端末の送信・取り込み。

ルールテストはJava 21以上と初回のFirestoreエミュレーター取得が必要です。取得先は `storage.googleapis.com` です。このクラウド環境ではネットワーク許可が必要です。テスト失敗や未実行を成功として扱わず、公開前に実行してください。

Playwrightはこのクラウド環境では `/usr/bin/chromium` を使います。ほかの環境では `CHROME_PATH` にChrome/Chromiumのパスを指定するか、Playwrightをインストールし設定の `executablePath` を調整してください。エミュレーター用のWeb設定は以下を `.env.local` に入れ、`npm run emulators` と別のターミナルで `npm run dev` を起動します。

Playwright付属のChromiumを使う場合は `npx playwright install chromium` の後に `CHROME_PATH=playwright npm run test:e2e` で実行できます。CIもこの方法を使います。Firebase SDKがNode向けに依存するgRPCは、既知の問題を修正した同一メジャーの `1.14.7` に固定しています。

```dotenv
VITE_FIREBASE_API_KEY=demo-key
VITE_FIREBASE_AUTH_DOMAIN=demo-ororo.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=demo-ororo
VITE_FIREBASE_APP_ID=1:1234567890:web:abcdef
VITE_USE_EMULATORS=true
```

エミュレーター接続は開発サーバーでのみ有効です。この設定のまま本番公開しないでください。

## 制限

本番プロジェクト作成・公開と、実際のiPhone/Android端末でのホーム画面追加は別途確認が必要です。端末のストレージがOSに削除されると未送信分は復元できません。同期済みの記録は、同じアカウントでログインし直して該当月を開くと取得できます。Firebaseの無料枠・認証の利用制限はプラットフォームの現行条件に従います。

## Googleログインと旧アカウントの移行

ログイン画面にはGoogleログインだけを表示します。通常はポップアップでアカウントを選び、ポップアップが拒否された場合は同一認証ドメインでのリダイレクトに切り替えます。「画面を切り替えてログイン」も選べます。Googleの選択画面を閉じた場合は勝手にリダイレクトせず、再試行できます。リダイレクトから戻ると家族共有画面を開き、招待リンクの情報を引き継ぎます。

`web.app` や独自ドメインを主に使いたい場合は、`VITE_FIREBASE_AUTH_DOMAIN` をその配信ドメインと同じにし、Google CloudコンソールのOAuth Webクライアントの「承認済みのリダイレクトURI」に `https://配信ドメイン/__/auth/handler` を追加してください。Firebase Hostingの認証ヘルパーが同じオリジンで動く構成が必要です。異なるサイトへの自動転送は、端末保存データの保存領域が変わるため行いません。

すでにメール/パスワードで使っている場合は、ログイン済みの端末の「Googleアカウントを連携」で移行してください。FirebaseのUIDを変えず、家族の所属・記録・未送信データを維持します。移行後も以前と同じGoogleアカウントを使ってください。既存アカウントは削除しません。移行が終わる前に旧プロバイダーを無効にしたり、別アカウントとして作り直したりしないでください。新しいアプリにはパスワード入力や再設定の画面はありません。

このクラウド環境でGoogleポップアップを検証する場合は `apis.google.com` の通信許可が必要です。任意のフォント・装飾CSSを取得するエミュレーターの外部アセットは、機能テストでは読み込みを省略できます。本物のGoogleアカウントでの認証・iOS実機での操作は、Firebaseのプロバイダーを有効にして公開後に確認してください。
